How to Use This Guide

Colour swatchesClick a swatch to copy var(--token-name) to your clipboard.
Code snippetsEach section includes copyable CSS or HTML — click Copy on the snippet header.
Block CSSAlways scope selectors to the block: .hero .title not .title.
Tokens onlyNever hardcode hex, px, or ms — use var(--…) from styles.css.
  • Tokens live in styles/styles.css inside :root, .dropin-design { }
  • Breakpoints: mobile default, 768px tablet, 1280px desktop — use min-width only
  • Section spacing is authored via section metadata (data-margin, data-padding) — not in block CSS
  • Button and form demos render inside <main> so global EDS styles apply on real pages
  • Commerce dropins use .dropin-design — theme via --btn-* / --form-* tokens and scoped overrides, never by editing scripts/__dropins__/
  • Icon tiles in the Icons section copy /icons/{name}.svg paths to the clipboard

Block CSS — responsive grid layout 
/* blocks/gallery/gallery.css */
.gallery {
  display: grid;
  grid-template-columns: repeat(var(--grid-columns), 1fr);
  gap: var(--grid-gutter);
  padding: 0 var(--grid-margin);
  max-width: var(--grid-max-width);

  grid-column: span 4; /* mobile: full width in 4-col grid */
}

@media (min-width: 768px) {
  .gallery .gallery__item {
    grid-column: span 4; /* tablet/desktop: 4 of 12 cols */
  }
}
Tablet-only styles — CSS Level 4 range syntax 
/* Use range syntax when a rule applies ONLY at tablet — avoids a second query to reset it.
   Browser support: Chrome 104+, Firefox 63+, Safari 16.4+ */

/* ❌ Old way — two queries just to cancel each other */
@media (min-width: 768px) {
  .hero .hero__aside { display: none; }
}
@media (min-width: 1280px) {
  .hero .hero__aside { display: block; }
}

/* ✅ Range syntax — clear intent, single query */
@media (768px <= width < 1280px) {
  .hero .hero__aside { display: none; }
}

/* ✅ Standard min-width still correct for tablet + desktop cascade */
@media (min-width: 768px) {
  .hero .hero__title { font-size: var(--type-heading-1-size); }
}
@media (min-width: 1280px) {
  .hero .hero__title { font-size: var(--type-display-size); }
}
Page structure & containment — how sections constrain content 
/*
 * EDS generates this HTML for every authored section:
 *
 *   <main>
 *     <div class="section">              ← full viewport width (can have bg color)
 *       <div class="default-content-wrapper">  ← constrained — max-w + padding auto-applied
 *         <!-- blocks and default content live here -->
 *       </div>
 *     </div>
 *   </main>
 *
 * styles.css applies to every inner wrapper automatically:
 */
main > .section > div {
  max-width: var(--grid-max-width); /* 1280px */
  margin: auto;
  padding: 0 var(--grid-margin);   /* 20px mobile → 56px desktop (alias auto-switches) */
}

/* Section vertical spacing (applied to the outer .section, not the wrapper) */
main > .section            { margin: var(--spacing-xxbig) 0; }  /* 48px mobile  */
@media (min-width: 768px)  { main > .section { margin: var(--spacing-large) 0; } }   /* 64px tablet  */
@media (min-width: 1280px) { main > .section { margin: var(--spacing-xxlarge) 0; } } /* 96px desktop */

/* First and last sections never carry a top/bottom gap */
main > .section:first-of-type { margin-top: 0; }
main > .section:last-of-type  { margin-bottom: 0; }
Full-bleed vs contained — two block layout modes 
/*
 * CONTAINED — block respects the section wrapper's max-width + padding (default).
 * You don't need to write max-width or padding on the block itself.
 * The section wrapper already handles it.
 */
.cards { display: grid; gap: var(--grid-gutter); }


/*
 * FULL-BLEED — block's background (or image) spans 100vw.
 * Override the section wrapper padding to zero on the block itself,
 * then re-apply horizontal padding on an inner content div.
 */
.hero {
  padding: 0;          /* remove inherited section padding so bg reaches edges */
}

.hero .hero__content {
  max-width: var(--grid-max-width);  /* re-apply containment on inner div */
  margin: auto;
  padding: var(--spacing-xxbig) var(--grid-1-margins); /* mobile: 20px sides */
}

@media (min-width: 1280px) {
  .hero .hero__content {
    padding: var(--spacing-xxbig) var(--grid-4-margins); /* desktop: 56px sides */
  }
}

/*
 * ✅ Horizontal padding ALWAYS uses grid margin tokens — never fixed px.
 *    var(--grid-1-margins) = 20px   (mobile / tablet)
 *    var(--grid-4-margins) = 56px   (desktop)
 */

EDS authored buttons

Global .button classes in styles/styles.css apply to links and <button> inside <main>. They read directly from --btn-* tokens (sizing, typography, colour, states). Size utilities (.btn-sm / .btn-md) go on a wrapper around the button.

Commerce dropin buttons

Adobe Commerce dropins inject .dropin-button at runtime with their own CSS. Do not edit files in scripts/__dropins__/. Instead:

  • Shared tokens live in :root, .dropin-design { } so dropins inherit GS brand colours
  • Dropin primary buttons map to --btn-primary-* (Forest #005640) — same as EDS .button.primary, not bright --color-brand-500
  • Dropin secondary buttons map to --btn-secondary-* (forest outline + text)
  • Shape + typography (height, padding, radius, uppercase, weight) are aligned via scoped .dropin-design .dropin-button overrides that reference --btn-*
  • Legacy dropin colour hooks --color-button-hover, --color-button-active, --color-button-focus remain for injected rules that still read them

EDS native forms vs Commerce dropins

Two parallel systems share the same --form-* token definitions in :root, .dropin-design { }:

  • EDS / authored content — main styles target native input, textarea, select, and choice controls with :not(.dropin-design *) so block forms get full GS styling automatically
  • Commerce dropins — inject their own markup/CSS (e.g. .dropin-input-*, .dropin-checkbox__*, .dropin-radio-button__*). Native field rules are excluded; dropins pick up GS colours via shared --color-* tokens (e.g. --color-alert-500 for errors) and choice control geometry via scoped CSS overrides that map dropin classes to --form-choice-* tokens
  • Never edit scripts/__dropins__/ — influence dropin forms only through token overrides and the .dropin-design selector blocks in styles/styles.css

SVG colour & hover techniques

All GS SVGs use fill="currentColor". This means colour is always set via CSS — never in the SVG file. Three patterns cover every use case.

Technique 1 — CSS color property  ·  inline SVG or decorateIcons()

Neutral grey
GS Green
GS Forest
GS Poppy
White on dark
CSS — set icon colour via color property 
/* The SVG uses fill="currentColor" — CSS color drives it */
.my-block .my-block__search-icon {
  color: var(--color-neutral-600);       /* default grey */
}

.my-block .my-block__search-icon:hover,
.my-block .my-block__search-icon:focus-visible {
  color: var(--color-gs-green);          /* hover green */
}

/* On dark background — flip to white */
.my-block--dark .my-block__search-icon {
  color: var(--color-neutral-50);
}

Technique 2 — CSS mask-image  ·  block CSS pseudo-elements (no extra HTML)

↑ Hover any button — icon colour transitions with the text via currentColor

CSS — mask icon in block CSS (no extra HTML needed) 
/* blocks/nav/nav.css — icon appears via ::before, no HTML changes */
.nav .nav__search-btn {
  display: inline-flex;
  align-items: center;
  gap: var(--spacing-xsmall);
  color: var(--color-neutral-700);
  transition: color var(--transition-fast);
}

.nav .nav__search-btn::before {
  content: '';
  display: inline-block;
  width: 20px;
  height: 20px;
  background: currentColor;            /* inherits color from parent */
  -webkit-mask: url('../../icons/search.svg') center / contain no-repeat;
  mask: url('../../icons/search.svg') center / contain no-repeat;
}

/* Hover: just change color — icon follows automatically */
.nav .nav__search-btn:hover {
  color: var(--color-gs-green);
}

Technique 3 — State toggle  ·  wishlist / like (outline ↔ filled via JS class)

↑ Click to toggle — border and icon colour change; no SVG swap needed

CSS + JS — wishlist toggle (single SVG, two states) 
/* blocks/product-card/product-card.css */
.product-card .product-card__wishlist {
  color: var(--color-neutral-600);          /* outline state */
  border-color: var(--color-neutral-300);
  transition: color var(--transition-fast), border-color var(--transition-fast);
}

/* Active (saved) — just swap color; SVG stays the same */
.product-card .product-card__wishlist.is-active {
  color: var(--color-gs-poppy);             /* filled red */
  border-color: var(--color-gs-poppy);
}

/* The icon element uses mask so it inherits color */
.product-card .product-card__wishlist .product-card__wishlist-icon {
  display: inline-block;
  width: 20px;
  height: 20px;
  background: currentColor;
  -webkit-mask: url('../../icons/heart.svg') center / contain no-repeat;
  mask: url('../../icons/heart.svg') center / contain no-repeat;
}
JS — toggle the is-active class on click 
// blocks/product-card/product-card.js
export default async function decorate(block) {
  const wishlistBtn = block.querySelector('.product-card__wishlist');
  if (!wishlistBtn) return;

  wishlistBtn.addEventListener('click', () => {
    const isActive = wishlistBtn.classList.toggle('is-active');
    wishlistBtn.setAttribute('aria-pressed', String(isActive));
    wishlistBtn.querySelector('.product-card__wishlist-label').textContent =
      isActive ? 'Saved' : 'Save';
  });
}
